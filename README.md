# メダカ出品アシスタント (medaka-app)

一眼レフで撮った写真フォルダから、**ヤフオク（オークタウン一括出品）用の CSV + 画像ZIP** までを
ブラウザだけで作るデスクトップ向け単一HTMLアプリ。

| 項目 | 内容 |
|---|---|
| 形態 | 単一HTML（`index.html`）+ PWA。ローカルで開くだけで動く |
| 対応ブラウザ | **Chrome / Edge / Brave**（`showDirectoryPicker` 使用のため Safari 不可） |
| バージョン | v2.0（Phase 1〜4 実装済み） |
| バックエンド | Google Apps Script（OCR と Gemini 画像加工のAPIキー保管庫）。**CSV/ZIP生成はGAS不要・完全ローカル** |
| 旧スマホ版 | `../medaka-app-pwa/`（撮影用PWA・別物） |
| スプレッドシート版 | `../medaka-gas/コード.js`（在庫シート運用 + シート側のZIP生成。CSV仕様はこちらと同一） |

---

## 使い方（全体フロー）

```
① 取込 → ② 編集 → ③ 出品 → 履歴
```

### ① 取込
1. 「📂 フォルダを選ぶ」で撮影フォルダを選択（ラベル1枚 → 個体3枚 …の並び前提）
2. 先頭から4枚ごとにラベルを自動推定。違う場合はサムネ下の「📋ラベル / 🐟個体」で切替
3. 「🔍 OCR一括実行」でラベル写真から **品種名・ランク・数量・管理番号** を抽出（Claude Haiku / GAS経由）
4. 緑枠 = AI入力。手で直したフィールドはOCR再実行でも上書きされない

### ② 編集
- **🤖 ChatGPTで整える（メイン）** … `gpt-image-2` の画像編集APIに「いい感じにして」と投げる
  - **正方形(1:1)にする** … 送る前にCanvasで**黒の余白を足して正方形化**してから渡す。
    引き伸ばさないので**ヒレの長さや体型が変わらない**（プロンプトでもアスペクト変形を禁止）
  - **背景を真っ黒に** … 背景・水面・容器の縁を黒へなじませる
  - **向きはAIにおまかせ** … 商品写真として見栄えの良い向きに（左右反転可）。
    気に入らなければ ⇄ ⇅ ↻ で**手動修正**でき、その修正はAI結果の上に重なる
  - 3つとも**個別にON/OFF**できる
  - **👎 ここを直す → その場で作り直し** … ダメな理由をチップ＋自由記述で伝えると、それを最優先指示にして再生成。
    「次回から毎回守らせる」にチェックすると **📝 AIへの指示メモ**に貯まり、**以降すべての加工に自動で反映**される
  - 料金の目安: low 約1円 / medium 約5円 / high 約25円（1枚あたり・要実測）
- Gemini（基本補正 / 背景黒 / ラメ・ヒレ強調 / シャープネス / AI構図）、Real-ESRGAN 解像度UP、正方形クロップ
- **表示サイズ 小/中/大/特大** … 加工前・加工後の並列サムネの大きさを切替（既定=中300px、localStorage保存）
- **明るさスライダー（0〜100）** … Canvas処理なので**完全無料**。動かすとその場で「加工後」に反映され、
  **見ながら選べる**。0にすると加工後表示が消えて元画像に戻る
  - **写真1枚ごとのスライダー**（各サムネの下）… 個体ごとに違う明るさにできる
  - **商品まとめてのスライダー**（カード右上・なし/弱25/中55/強85のプリセット付き）… その商品の全個体を同じ値に。
    ドラッグ中は先頭1枚だけ即時プレビュー、離すと全個体に適用
  - 既定は **0（無補正）**。**AI加工した写真だけ従来どおり 55（中）から**始まる（そこから自由に調整可）
  - **明るさはAIのキャッシュキーに含めない**ので、スライダーを動かしてもAIの再実行（課金）は起きない
- **🎛 この1枚を調整**（各サムネ下の折りたたみ）… 写真ごとに **コントラスト / 彩度 / 色温度 / シャープ**。
  すべてCanvas処理で**無料・即反映**。調整済みの写真は見出しに ● が付く
  - **🧹 AIゴミ取り** … その1枚だけ Gemini で浮遊物・ゴミを除去（約6円）。他の写真は消費しない
  - **📋 他の写真にも** … 追い込んだ調整値を同じ商品の残りの写真にコピー
  - **↺ リセット** … その写真の調整・回転・反転をすべて解除
- **↻ 90°回転** … 縦位置で撮った写真の向き直し（押すたびに90°、Canvas・コスト0）
- **⇄ 左右反転 / ⇅ 上下反転** … Canvasで即時反転（AI不要・コスト0）。もう一度押すと解除。
  AI加工の有無にかかわらず使え、AI再加工しても反転は維持される。反転画像はそのまま③出品の画像に使われる
  （反転は「好みの加工」ではないので📚マイスタイルの学習には未反転の画像を使う）
- 「💾 保存」すると **📚マイスタイル**（元画像＋加工後のペア）を学習し、次回以降の加工が好みに寄る

### ③ 出品（Phase 3）
- **⚙ オークタウン共通設定** … カテゴリID・開催期間・発送元・配送方法など37項目。localStorage に保存
- **📝 説明文テンプレート** … `{品種} {ランク} {数量} {管理番号} {備考} {タイトル} {送料}` が使える。
  値が空になったプレースホルダだけの行（例: `【備考】`）は自動削除。見出し行はそのまま残る
- **🖼 出品画像の書き出し** … 一眼レフの10MB級JPEGやGemini加工後のPNGを、
  **JPEG化 + 長辺リサイズ（既定1600px）+ 1枚あたり上限（既定3MB）** に自動変換。
  EXIFの回転を反映してから書き出すので縦位置写真が横倒しにならない。上限超過時は「画質を下げる → それでも超えれば縮小」の順に自動調整
- 商品ごとに **タイトル（自動生成／手編集可・全角65文字カウンタ付き）／開始価格／備考** を設定
- 生成前チェック … タイトル空 / 開始価格が数字でない / 画像0枚 / カテゴリID未設定 は**中止**、
  65文字超・画像6枚以上・管理番号の空や重複は**確認ダイアログ**
- **📦 CSV + 画像ZIP を生成** で以下を1つのZIPにしてダウンロード
  - `auctown_YYYYMMDD_HHMMSS.csv`（44列・**Shift_JIS**。UTF-8(BOM)も選択可）
  - 画像 `<管理番号>_01.jpg` … `_05.jpg`（1商品あたり最大5枚）
- 「✨加工後画像を優先」ON なら②で加工した画像、なければ元画像を使用
- 「📋ラベルを1枚目に」ON ならラベル写真が `_01` になる

### 履歴（Phase 4）
- 生成したロットを IndexedDB に保存（日時 / フォルダ名 / 件数 / CSV本文）
- 商品ごとに **出品中 → 落札済 → 発送済（発送日を自動セット）→ 取消** を切替、ロット単位の一括「発送済」も可
- **📄 CSV再ダウンロード**（画像は保持しないのでCSVのみ）、**履歴をCSVエクスポート**（UTF-8 BOM・Excel用）

## 設定タブ

GAS Webhook URL を入れておく（OCR・Gemini加工に必要）。
GAS側のスクリプトプロパティに `CLAUDE_API_KEY` / `GEMINI_API_KEY` / `REPLICATE_API_TOKEN` /
**`OPENAI_API_KEY`**（ChatGPTで整える用）が要る。

**ChatGPT連携を使うための準備**
1. `../medaka-gas/コード.js` の `handleOpenAiEdit()` と `doPost` の `openai_edit` 分岐を GAS プロジェクトに反映
2. スクリプトプロパティに `OPENAI_API_KEY`（https://platform.openai.com/api-keys で発行）を追加
3. 「デプロイを管理」→ 既存デプロイを**新バージョンで再デプロイ**（URLは変わらない）

APIキーはGAS側にだけ置き、ブラウザには一切出さない（CORS回避も兼ねる）。
**③出品タブの CSV/ZIP 生成はネット接続もGASも不要。**

## 実装メモ

- **Shift_JIS 変換**: CP932 の Unicode→SJIS 対応表（9280文字）を base64 で `index.html` に内蔵。
  外部ライブラリなしでオフライン変換。表に無い文字は `?` に置換し、生成時にトースト警告を出す。
  `〜`(U+301C) など慣用マッピングは `SJIS_FALLBACK` で補完
- **ZIP 生成**: 無圧縮(store)方式の自前ZIPライター（CRC32 + local header + central directory + EOCD）。
  JPEGは既に圧縮済みなので store で十分。ファイル名はASCIIに正規化するので文字化けしない
- **タイトル長**: ヤフオク仕様に合わせ「全角1 / 半角0.5」で数え、65を超えたら管理番号を残して先頭側を切り捨て
- **加工後画像の組み立て**: `editState[i]` に **`baseBlobUrl`（AI加工結果そのもの）** と
  **`editedBlobUrl`（= base → 明るさ/コントラスト/彩度/色温度/シャープ → 回転 → 反転）** を持たせ、
  `recomposePhoto(i)` で毎回組み立て直す。調整値は `photoAdjust[i]`（`ADJ_DEFAULT` 参照）。
  明るさと反転はAI結果に焼き込まないので、何度でもやり直せるしAIを再実行しても設定が残る。
  処理は長辺1800pxで行う（出品時に長辺1600pxへ縮むため実質フル品質）
- **画像の対応付け**: `products[i].labelIdx / specimenIdxs` が写真配列のインデックス。
  加工後画像は IndexedDB(`medaka-edit` / `edited`)、履歴は同DBの `history` ストア（v3）

## 検証済みの動作

- 生成ZIP: `zipfile.testzip()` でCRC検証OK / CSVが `cp932` でデコード可能 / 44列
- 説明文: HTMLモードで `<br>` 変換、`【発送について】` などの見出しが消えないこと
- 履歴: IndexedDB への保存・状態変更・発送日自動セット・フィルタ・一括更新・全削除（Chrome CDPで実行）
- **実画像でのエンドツーエンド**（Chrome CDP で `buildAuctownExport()` を実行し、生成ZIPをPythonで検証）
  - 4000×3000 / 約10MB のJPEG → **1600×1200 / 約1.3MB** に変換
  - EXIF Orientation=6（保存3000×4000）の縦位置写真 → **1600×1200 で正立**
  - 加工後PNG → JPEG に変換して同梱
  - CSVの画像列とZIP内のファイル名が一致、2商品8枚で生成時間 約1.3秒
  - 開始価格が数字でない場合に生成が中止されること

### テストのやり方（再現用）

`__testimg/` に PIL で作った実JPEG（EXIF回転付き含む）を置き、`index.html` のコピーを
Chrome ヘッドレス（`--remote-debugging-port` + `--allow-file-access-from-files`）で開いて
CDP の `Runtime.evaluate` から `photos` / `products` / `editState` を差し込み、
`window.downloadBlob` を差し替えて生成ZIPを base64 で回収 → Python の `zipfile` + `PIL` で検証する。
（`--virtual-time-budget` を使うとIndexedDBや画像デコードが完了前に打ち切られるので使わないこと）
